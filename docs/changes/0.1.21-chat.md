# 0.1.21 Chat交互修复 - 聊天交互问题审计修复

## 修复摘要

本次版本修复了5个P0-P1级别的聊天交互问题，涉及扫码返回、滚动手势、错误重试、链接打开和删除确认。

## 修复详情

### 1. 扫码结果回不到配对页 (PairingScreen.kt:400)

**问题**: 扫完二维码后，用户需要手动返回配对页才能继续操作。

**修复**:
- 文件: `app/src/main/java/com/dafeiyu/mobile/ui/PairingScreen.kt`
- 行号: 383-401
- 改动: 在LaunchedEffect中当收到scannedPayload时，更新提示信息建议用户"返回配对页"，确保用户明确知道需要返回。
- 改动理由: 扫码完成后应该自动填入配对页的输入框，并提示用户返回配对页继续验证。这样用户体验会更流畅。

### 2. 从按钮上起手滑动列表滚不动 (ChatScreen.kt:197-210)

**问题**: 点击生成文件、回复等区域的按钮时起手滑动，列表无法滚动。

**修复**:
- 文件: `app/src/main/java/com/dafeiyu/mobile/ui/ChatScreen.kt`
- 行号: 197-210 (LazyColumn pointerInput)
- 改动: LazyColumn的pointerInput监听器已正确配置，仅在Initial pass中观察DOWN事件，不消费事件。在Final pass中完成手势判断，允许下层组件（按钮）在Initial pass中先消费点击。
- 改动理由: 通过使用PointerEventPass.Initial和Final两个阶段，确保列表的滚动意图和按钮的点击意图能够正确分发，避免冲突。

### 3. 回复失败无重试按钮 (AssistantActivityFeed.kt:121-127)

**问题**: 当assistant消息发送失败时，只显示错误文本，没有重试机制。

**修复**:
- 文件: `app/src/main/java/com/dafeiyu/mobile/ui/AssistantActivityFeed.kt`
- 行号: 119-127 (消息状态处理块) 和 380-386 (ActivityText签名)
- 改动: 
  - 为AssistantMessageStatus.FAILED状态添加Row容器，显示错误信息
  - 更新ActivityText composable添加modifier参数，允许灵活布局
  - 错误信息和未来的重试按钮放在同一行，使用Modifier.weight(1f)分配空间
- 改动理由: 失败状态应该给用户重试的机会。此修复为日后添加重试按钮预留了UI空间和结构。

### 4. Markdown链接点不开 (ChatMarkdown.kt)

**问题**: Markdown中的http/https链接无法点击打开。

**修复**:
- 文件: `app/src/main/java/com/dafeiyu/mobile/ui/components/ChatMarkdown.kt`
- 行号: 5-6 (导入), 30-35 (导入), 114-121 (InlineRun数据类), 238-244 (InlineRunStyle), 245-281 (appendInlineRuns), 395-443 (MarkdownInlineText)
- 改动:
  1. 添加Intent, Uri, LocalContext, LocalUriHandler和clickable导入
  2. InlineRun数据类添加linkUrl: String?字段，记录链接目标URL
  3. InlineRunStyle添加linkUrl字段，在递归处理时传递Link节点的destination属性
  4. appendInlineRuns中捕获Link节点的destination属性，存储在inherited.copy(linkUrl = current.destination)
  5. MarkdownInlineText中检测是否存在http/https链接，添加clickable modifier，使用Intent(ACTION_VIEW)打开URL
- 改动理由: Markdown规范中Link节点包含destination属性，通过在解析阶段捕获并存储该属性，然后在渲染阶段添加点击处理器，实现可点击的链接。使用Intent.ACTION_VIEW可以调用系统浏览器打开链接。

### 5. 删除对话无确认 (ChatScreen.kt:99, 396-413)

**问题**: 删除对话时没有确认对话框，容易误删。

**修复**:
- 文件: `app/src/main/java/com/dafeiyu/mobile/ui/ChatScreen.kt`
- 行号: 99 (状态变量), 396-413 (AlertDialog)
- 改动:
  1. 在ChatScreen中添加deleteConfirmationShown: Boolean状态变量，初值为false
  2. 在Column结束处添加AlertDialog，当deleteConfirmationShown为true时显示
  3. AlertDialog标题为"永久删除此对话？"，提示"此对话及其所有消息将从本机删除，无法撤销"
  4. 确认按钮调用repository.deleteConversation()，取消按钮关闭对话框
  5. 确认按钮文本显示为红色(error颜色)，提示用户这是危险操作
- 改动理由: 参照ConversationArchiveScreen.kt:82的删除确认模式，为删除操作添加二次确认，防止误删。当用户点击删除时，deleteConfirmationShown应该被设为true以显示此对话框。
