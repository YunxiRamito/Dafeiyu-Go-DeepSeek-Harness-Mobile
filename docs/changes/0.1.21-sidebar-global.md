# 0.1.21 侧栏与全局交互修复

## 修复概述

本次修复解决三个 P0-P1 级别的交互逻辑问题，使侧栏在用户主动关闭或点击主区域时才收起，并为所有删除操作添加永久删除确认框。

## 修改列表

### 1. MainActivity.kt (第 350 行)

**修改内容：**
- 行号：350
- 变更：`onConversationChanged = { menuOpen = false; route = "home" }` → `onConversationChanged = { route = "home" }`
- 理由：移除 menuOpen = false，使侧栏不会在选择工作区或对话时自动关闭。仅保留 route = "home" 以确保导航状态正确。侧栏现在仅在用户显式点击关闭按钮或点击主区域时关闭。

### 2. WorkspaceSidebar.kt

#### 2.1 状态变量添加 (第 99 行附近)

**修改内容：**
- 添加两个新的状态变量：
  - `var workspaceToDeleteId by remember { mutableStateOf<String?>(null) }`
  - `var conversationToDeleteId by remember { mutableStateOf<String?>(null) }`
- 理由：用于跟踪待删除的工作区和对话 ID，以触发确认对话框。

#### 2.2 工作区选择逻辑 (第 156-171 行)

**修改内容：**
- 工作区删除改为设置状态变量而非直接删除：`onDelete = { workspaceToDeleteId = workspace.id }`
- 理由：延迟删除至用户确认后执行。

#### 2.3 对话选择逻辑 (第 196-224 行)

**修改内容：**
- 移除对话选择时的 `onClose()` 调用（原第 209 行）
- 对话删除改为设置状态变量：`onDelete = { conversationToDeleteId = conversation.id; false }`
- 理由：用户选择对话或对话行时侧栏应保持打开。删除操作现在先显示确认框。

#### 2.4 确认对话框添加 (第 260 行附近)

**修改内容：**
- 添加工作区删除确认对话框：
  ```kotlin
  val workspaceToDelete = repository.workspaces.firstOrNull { it.id == workspaceToDeleteId }
  if (workspaceToDelete != null) {
      AlertDialog(
          onDismissRequest = { workspaceToDeleteId = null },
          title = { Text("永久删除此工作区？") },
          text = { Text(""${workspaceToDelete.name}"及其所有对话将从本机删除，无法撤销。") },
          ...
      )
  }
  ```

- 添加对话删除确认对话框：
  ```kotlin
  val conversationToDelete = repository.conversations.firstOrNull { it.id == conversationToDeleteId }
  if (conversationToDelete != null) {
      AlertDialog(
          onDismissRequest = { conversationToDeleteId = null },
          title = { Text("永久删除此对话？") },
          text = { Text(""${conversationToDelete.title}"及其消息将从本机删除，无法撤销。") },
          ...
      )
  }
  ```

- 理由：参照 ConversationArchiveScreen.kt 的永久删除确认模式，向用户明确显示删除后果，避免意外删除。

### 3. ExtensionsScreen.kt

#### 3.1 状态变量添加 (第 61 行附近)

**修改内容：**
- 添加：`var extensionToDeleteId by rememberSaveable { mutableStateOf<String?>(null) }`
- 理由：跟踪待删除的拓展 ID，以触发确认对话框。

#### 3.2 删除按钮逻辑 (第 309-331 行)

**修改内容：**
- 删除按钮的 onClick 改为设置状态变量：`onClick = { extensionToDeleteId = selected.id }`
- 移除原有的直接调用 `deleteLocalExtension`
- 理由：将删除操作延迟至用户在确认对话框中确认后执行。

#### 3.3 确认对话框添加 (第 376 行附近)

**修改内容：**
- 在 showImport 对话框之后添加拓展删除确认框：
  ```kotlin
  val itemToDelete = allItems.firstOrNull { it.id == extensionToDeleteId }
  if (itemToDelete != null) {
      AlertDialog(
          onDismissRequest = { extensionToDeleteId = null },
          title = { Text("永久删除此拓展？") },
          text = { Text(""${itemToDelete.name}"将从应用私有目录删除，无法撤销。") },
          confirmButton = {
              TextButton(onClick = {
                  // 执行实际删除逻辑
                  ...
              }) { Text("永久删除", color = colors.error) }
          },
          dismissButton = { TextButton(onClick = { extensionToDeleteId = null }) { Text("取消") } },
      )
  }
  ```

- 理由：在 ExtensionsScreen.kt:309-331 调用删除函数之前添加确认，避免用户误删本地拓展。

## 验证要点

- 选择工作区时侧栏保持展开
- 选择对话时侧栏保持展开
- 归档对话时侧栏保持展开
- 删除前显示确认对话框，明确说明"永久删除，无法撤销"
- 点击主区域或显式关闭按钮时侧栏收起
- 创建新对话时侧栏仍会自动关闭（用户体验优化）
